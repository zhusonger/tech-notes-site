# Tech Notes · 个人技术主页

暖米白 + 橙色的个人技术主页，前台 5 个页面（首页、博客列表、博客详情、项目、简历），
外加一套 `/admin` 内容管理后台。前端工程按一份界面设计稿实现，采用响应式重排。

前台本身是纯静态产物；后台需要服务端（httpOnly 会话、SQLite、TOTP）。因此整站由
**同一个 Express 进程**同时提供 API 与静态文件 —— 同源才不必处理跨站凭证与 CORS。

## 技术栈

前台：React 18.3 · TypeScript（strict）· Vite 5 · Tailwind CSS v4 · react-router-dom 6

后台：Express 5 · `node:sqlite`（Node 26 原生，无 ORM）· otplib（TOTP）· qrcode · helmet · express-rate-limit

## 数据归属

**内容只有一个来源：后台数据库。** 前台不再维护自己那份 `src/data/site.ts` 内容副本。

```
SQLite（后台写入）
  └─ server/content.mjs  readContentDoc()  ──┐
                                             ├─→ shared/derive.mjs  presentContent()
shared/content.mjs（种子 / 前台兜底）─────────┘        │
                                                    ├─→ GET /api/content   → 前台页面
                                                    └─→ DEFAULT_CONTENT    → 接口不可用时兜底
```

三条约束，缺一条就会出现「后台改了、前台没变」或「断网时页面变样」：

1. **`shared/content.mjs` 是唯一的内容源**：服务端首次启动用它灌库（`db.mjs` 的
   `seedIfEmpty`），前台也用它生成兜底内容。种子与兜底同源，结构上不可能分叉。
   这个一致性由 `api-smoke` 的「库内容与前台兜底内容结构一致」断言守着。
2. **展示串只在 `shared/derive.mjs` 生成一次**：`1.8k 阅读`、`2026.08.24`、`约 5 分钟`
   这类字符串由 `presentContent()` 统一产出，服务端与前台调用同一个函数。分成两处写，
   就一定有对不上的那天，而且只在断网时才暴露。
3. **正文渲染走 React 节点，不拼 HTML 字符串**（`src/lib/markdown.tsx`）：正文由作者自由撰写，
   渲染路径一旦变成 `dangerouslySetInnerHTML` 就是一个存储型 XSS。不做转义白名单，
   而是从结构上不给它出现的机会 —— `check:routes` 里有一条注入断言锁着这件事。

对外接口（匿名可读，无需会话）：

| 接口 | 说明 |
| --- | --- |
| `GET /api/content` | 整站内容：`site` / `home` / `resume` / `projects` / `posts` / `filters` / `stats` |
| `GET /api/content/posts/:slug` | 单篇详情：正文、目录、上下篇、相关文章、作者卡 |

两个接口都只返回 `published` 的文章 —— 草稿与回收站里的内容**不会**离开服务端。
响应带 `Cache-Control: no-store`，所以后台一保存，前台刷新即变。

前台侧的配合：`src/data/SiteContent.tsx` 在挂载时取 `/api/content`，失败则回落到
`shared/content.mjs` 的兜底内容，并在页面顶部挂一条「内容服务暂时不可用」的提示 ——
宁可明说降级，也不让人对着一份过期内容做判断。

### 访客明细与隐私边界

后台的「访客记录」是本站**唯一**落明文的地方，值得单独说明：

```
访客请求（页面外壳）
  ├─ page_views   visitor = hash(ip|UA|日)   → 仪表盘的长期趋势，永不落明文
  └─ visitor_logs ip + UA + 路径 + 时间       → 后台「访客记录」屏（IP / 地区 / 设备）
```

两条链路同一时刻写入、互不依赖，删掉明文那条**不影响**匿名统计的历史（这是刻意的：
匿名趋势的价值在长期，明文明细的价值在近期排查，保留期本来就不同）。

| 项 | 口径 |
| --- | --- |
| 写入范围 | 只写页面外壳请求，且**排除 `/admin/*`** —— 否则天天泡在后台的管理员会变成最活跃的访客 |
| 保留期 | 30 天（`VISITOR_RETENTION_DAYS`），独立的清理定时器，与审计日志的保留期互不影响 |
| 可见范围 | 仅在登录态下可读（`/api/admin/visitors` 未登录返回 401）；**公开内容接口一律不含它** |
| 地区解析 | 离线库 ip2region（`server/geo.mjs`）—— **解析过程不出网**：拿访客 IP 去调第三方 API，等于把访客的 IP 送给那个第三方。（库文件本身首次会联网获取一次，但那不涉及任何访客数据） |
| 设备解析 | `server/ua.mjs`，只做「浏览器 / 系统 / 设备类型」的粗归类，不落指纹 |
| 降级 | 地区库缺失时地区一列留空，**不阻塞请求，界面也不额外弹提示**（库几秒后自己到位） |

地区库本身约 11 MB，**既不进版本库也不进镜像** —— 它是一份可重新获取的公开数据。
改为按需获取：首次有人打开访客列表时，服务端在后台拉一次（不阻塞当次请求），
落到持久化目录，下次访问即可看到。想预热也可以手工 `npm run fetch:geo`。

## 本地开发

```bash
npm install
npm run fetch:geo    # 可选：预热离线地区库到 data/（约 11 MB；不跑也行，首次看访客页会自动拉）
npm run dev          # 前台 http://localhost:5173，热更新（只有前端，无 API）
npm start            # 完整应用（API + 静态产物）→ http://127.0.0.1:18007/admin
```

`npm run dev` 起的是 vite dev server，**不带后台 API**。前台页面本身不依赖 API，所以它照常可用；
要在开发态点后台，用 `npm start`（需先 `npm run build` 出 `dist/`）。

后台首次启动会创建管理员：给了 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 就用它们；没给则随机生成
一个口令并**只打印这一次**（终端或 `docker logs` 里能看到），同时置 `must_change_password`。

### 首次启动产生的目录

后台跑起来会在项目根建 `data/`，里面是 SQLite 库（含 WAL）与 2FA 主密钥 `.app-secret`。
两者都不能进版本库 —— `.gitignore` 按 **`/data/`** 根锚定排除（写成 `data/` 会连带把
`src/data/` 一起忽略掉，这个坑踩过一次）。离线地区库（约 11 MB）也落在这里：
`data/ip2region_v4.xdb` —— 它同样不入库，那是可重新获取的公开数据，不是本站源码。

地区库的落点是**持久化目录**，与数据库放在一起。这不是随手选的：容器根文件系统是
`read_only`，`/app/data` 是那里唯一可写的挂载点，而且它跨容器重建保留 ——
「只需要拉一次」才成立。探测顺序 `IP2REGION_XDB` → 持久化目录 → `vendor/`
（最后一个是旧镜像的内置位置，仅为兼容保留）。

## 容器化部署

仓库自带 `Dockerfile`，镜像里跑的是 `server/index.mjs` —— 静态资源与后台 API 在同一个进程，
因此不需要额外的反向代理就能直接访问 `/admin`。

```bash
docker build -t tech-notes-site .

# 数据目录必须挂出来，原因见下
mkdir -p data
docker run -d --name tech-notes-site \
  --read-only \
  -p 127.0.0.1:18007:18007 \
  -v "$PWD/data:/app/data" \
  tech-notes-site
```

容器把宿主机的 `./data` **bind mount** 到 `/app/data`（SQLite 库 + 2FA 主密钥 + 媒体上传）。
这是**必须**的，两个原因：

- 容器根文件系统是 `read_only`，不挂载的话进程直接起不来；
- 就算起来了，每次重建都会换一份数据与一把新主密钥，已绑定的两步验证会全部解不开。

镜像里**不带**离线地区库（约 11 MB）：构建期不为它联网，运行期首次打开访客列表时
在后台拉一次，落到 `/app/data`。所以第一次打开那一页地区列是空的，刷新一下就有。
想省掉这一次等待，可以在宿主机先跑 `npm run fetch:geo` 预热 —— 它落 `./data`，
正好就是上面挂进容器的那个目录。

`/healthz` 是健康端点。接反向代理时注意 `TRUST_PROXY` 默认为 1（信任一层代理头），
设错会让所有访客 IP 都记成 `127.0.0.1`，地区解析与限流随之失准。

## 本机快速预览（不建容器）

不依赖 Docker，直接在本机把构建产物跑起来：

```bash
npm run deploy:local # 构建 + 起完整应用（含后台），http://127.0.0.1:18007
npm start            # 同上但跳过构建，直接跑已有的 dist/
```

只想看一眼前台、不愿意起后台进程时，还有个零依赖的纯静态服务：

```bash
npm run serve        # 零依赖静态服务 dist/，带 SPA 回退与 /healthz
PORT=9000 npm run serve          # 换端口
HOST=0.0.0.0 npm run serve       # 换绑定地址（默认只绑 127.0.0.1，仅本机可访问）
```

两者分工要说清楚：`scripts/serve.mjs` **只发静态文件，没有 `/api`**，所以从它的端口进去
点 `/admin` 是一个永远登不上的空壳；`server/index.mjs` 才是正式运行路径（静态文件 + 后台 API
同一个进程），容器里跑的也是它。

`scripts/serve.mjs` 的行为：深链接刷新回退到 `index.html`、带 hash 的 `/assets/*` 长缓存、
`index.html` 不缓存。缺失的静态资源仍如实返回 404，不会被伪装成 200。

### 可选：开机自启

不想走容器、想让它在开发机上常驻时，用系统自带的进程管理器托管 `npm start` 即可：
macOS 用 launchd（`~/Library/LaunchAgents/*.plist`），Linux 用 systemd。

两件事必须注意：进程的工作目录要设成项目根（否则读不到 `dist/` 与 `data/`），
`DB_PATH` 要指向一个持久目录 —— 否则换一次启动就换一份库，内容看起来像「丢了」。

日志落在 `logs/serve.log` 与 `logs/serve.err.log`。plist 里 node 路径写的是
`/opt/homebrew/bin/node`（Homebrew 装的 v26），换过 Node 就要改这一行。

注意这份 plist 起的是**纯静态**的 `scripts/serve.mjs`（8080），因此它只服务前台；
要在这台 Mac 上常驻带后台的版本，把 plist 里的
`scripts/serve.mjs` 换成 `server/index.mjs` 即可 —— 但别再和 `npm start` 用同一个端口。

## 校验

```bash
npm run typecheck    # tsc --noEmit
# 渲染校验：前台 7 条路由 + 后台 12 条路由，另加 13 个组件直渲断言（脚本结尾会打印总数）
npm run check:routes

# 地区解析断言需要离线库在位（缺库时会跳过那一条，不判失败）
npm run fetch:geo              # 加 --check 则只校验现有文件、不联网

# 后台 API 端到端冒烟（覆盖登录/2FA/内容/设置/日志/维护模式/公开内容接口/访客记录，条数以输出为准）
node scripts/api-smoke.mjs admin@test.local '口令' http://127.0.0.1:18007

# 「彻底删除文章」不可逆，默认跳过，需要时显式打开
SMOKE_ALLOW_DELETE=1 node scripts/api-smoke.mjs admin@test.local '口令' http://127.0.0.1:18007
```

本脚本会真的改数据（绑定 2FA、重置恢复码、改显示名、切换文章状态、建删一篇测试文章与
一个测试项目、打乱再还原项目顺序），**只应指向一次性实例**。

脚本开头那组内容是**匿名**请求（此时还没有任何会话 Cookie），因此它同时证明了
「前台不依赖登录态」和「草稿不外泄」；其中一条是端到端闭环判据 ——
后台把文章移入回收站后，再去读 `/api/content`，该文章必须**当场**不在列表里。
只断言后台自己的列表变了，是证明不了前台跟着变的。

`check:routes` 里 `/admin*` 那几条断言值得留意：SSR 下 `useEffect` 不执行，守卫会停在
「正在校验会话…」。这恰好是有意义的断言 —— 未登录时后台内容一个字都不该出现在首屏 HTML 里。

前台那几条断言跑的是**兜底内容**（校验环境里没有 `SiteContentProvider`，也没有网络），
所以它们锁的是「接口挂掉时前台仍然渲染得完整、不白屏」。库侧与兜底侧的一致性由
`api-smoke` 那条结构比对断言负责 —— 两边各测一半，合起来才是完整的。

代价是**走路由断言不到任何后台页面的正文**（守卫先短路了）。要验页面自身，用脚本里
`pages` 那组：绕开路由与守卫直接渲染组件（SSR 不跑 effect，因此不会发请求），
在其中断言页头文案与加载态骨架。此前「待开发」占位页那条自述清单，随占位页一起删除了 ——
后台 14 屏全部落地后，已不存在「未落地的入口」这一说。

## 内容状态

- **新增「访客记录」屏：展示站的来源明细**（2026-09-23）。按访客（IP 维度）聚合，给出
  归属地区、访问设备、首次/最近访问与累计浏览数，支持时间范围与 IP 关键词筛选、页码分页。
  这一屏是**设计稿之外**的新增（设计稿 14 屏里没有它），所以有三处自己定的口径：
  1. **地区靠离线库，解析不出网。** `server/geo.mjs` 自实现 ip2region IPv4 xdb 查询
     （向量索引定位分区 + 14 字节步长二分），依赖 `data/ip2region_v4.xdb`（约 11 MB，
     首次打开这一页时在后台自动获取；不进版本库也不进镜像）。**刻意不引 npm 包**：官方已不再维护 Node binding，
     第三方实现与 xdb 格式的兼容性要自己盯，反倒不如把这段短逻辑握在手里；
     也**刻意不调在线 API** —— 拿访客 IP 去查第三方，等于把访客的 IP 送给那个第三方。
  2. **设备只做粗归类。** `server/ua.mjs` 给出「浏览器 · 系统」与四类设备
     （桌面 / 移动 / 平板 / 爬虫），不构建指纹。
  3. **分页用页码而不是「加载更多」**（操作日志用的是后者）：访客名单是有边界的，
     用户会带着「上个月杭州来的那个是谁」这类问题来回翻，页码比一路下滚更好用。
     分页数按**独立 IP 数**算，越界页码收敛到最后一页而不是报错。
  明细口径（明文范围、保留期、可见范围、降级行为）见上文「访客明细与隐私边界」；
  接口的边界由 api-smoke 的 15 条断言锁住，其中一条专门守着「后台自己的访问不进明细」。
- **开源项目卡片支持点击跳转仓库**（2026-09-23）：`ProjectCard` 在填了仓库地址时整卡渲染成
  `<a target="_blank" rel="noreferrer noopener">`，留空则退回 `<article>`（**绝不渲染空 href**，
  那会让点击变成刷新当前页）。仓库地址的服务端校验只放行 `http(s)://`，写别的会被 400 拦下 ——
  留个 `javascript:` 的口子就等于让「填一个项目」变成「在卡片上挂一段脚本」。
  两种形态各有断言守着（`check:routes` 里的 `ProjectCard(仓库链接)` 与 `ProjectCard(未填仓库地址)`）。
  **注意一个刻意的取舍**：项目卡片的仓库地址**没有默认值** —— 种子里留空就渲染成不可点
  （`<article>`），填了才变成链接。早先种子会按 slug 合成一个 `https://github.com/<账号>/<slug>`，
  于是每张卡片都挂着一条没人核对过的地址：**它要么真实存在，要么就是个 404**，
  而后者比「没有链接」更糟 —— 读者会以为自己点错了，实际上那条地址从来不存在。
- **前台与后台的数据通路已打通**（2026-09-22）：前台从 `/api/content` 读内容，内容源是后台
  数据库；`shared/content.mjs` 只承担「首次建库的种子」与「接口不可用时的兜底」两个角色。
  闭环判据在 `api-smoke` 里：后台把文章移入回收站后，公开内容接口当场不再返回它；
  另有一条结构比对断言，防止库侧与兜底侧在字段层面漂移。详见上文「数据归属」。
  **注意**：内容能改的范围取决于后台已落地到哪一屏。当前文章（含正文）、项目、**首页文案与配图**、
  **简历页各节**、**媒体库**、**分类与标签**都已落地，后台设计稿 14 屏全部完成。
- **「首页内容」屏改完前台立刻变**（2026-09-22）：首屏 / 关于我 / 技术栈三个模块（外加只读的页脚）
  按**一键一份**的方式读写 `site_sections` 的 `home` 区块，前台 `presentContent()` 直接按这个文档
  形状拼装，中间没有第二份副本。所以保存后刷新首页即可见，不存在「后台改了、前台还是旧的」。
  两处刻意的设计取舍：
  1. **提交是整份区块文档，不是字段补丁。** 嵌套数组（技术栈条目、数据条）上「空数组代表清空
     还是代表没改」没有唯一解，做深合并只会把歧义藏进合并逻辑里。
  2. **页脚在这里只读。** 页脚的年号区间、备案号、社交链接已在「站点设置」可编辑，
     同一份数据开两个写入口必然打架，所以这屏只显示并指路。
  校验口径来自 `shared/sections.mjs` 的单一规格（前端画字数计数、后端做拒收用的是同一份），
  所以不会出现「界面上还能敲、保存却被拒」。审计记的是**逐字段比对后的真实改动**
  （例：`更新首页内容 · 首屏 · 中文名、拉丁名`），整份提交不会被记成「全字段都改了」。
- **「简历编辑」屏把简历页从写死变成可编**（2026-09-22）：概要 / 工作经历 / 技能与教育 / 联系方式
  四个页签对应 `site_sections` 的五个区块（「概要」页签管个人概述与核心竞争力两节），提交同样是
  整份区块文档。三处刻意的取舍：
  1. **模块顺序与显示状态走独立的小区块**（`resumeLayout` 的 `order` + `hidden`），不进草稿、
     点一下即提交 —— 拖拽与隐藏是结构性操作，和「打字还没保存」挤进同一个保存按钮，
     会让「有 X 项未保存」这句话的指代变模糊。
  2. **站点级事实（姓名 / 头衔 / 城市 / 邮箱 / GitHub / 头像 / 教育）在这屏只读**，指路
     「站点设置 → 作者资料」；同一份数据开两个写入口必然打架。顺带把此前只有种子值、
     没有编辑入口的四个教育字段补进了作者资料分组。
  3. **成句的要点用多行输入框**（规格里的 `itemType: 'textarea'`）：核心竞争力、经历要点这些
     是整句话，单行输入框会把 240 字上限藏起来 —— 看着还能填，其实早已溢出。
  另外，模块清单取自 `shared/sections.mjs` 的 `RESUME_SECTIONS`（真实五节），没有照抄设计稿上那
  六个模块：设计稿里的「项目经历」「开源贡献」在真实简历页已并入工作经历 / 删除，面板不该列前台
  不存在的模块。设计稿上的「添加模块」也没实现 —— 简历的节是定数，做成按钮只会是个假按钮。
  面板里带底色的行是**当前编辑的那一节**（与设计稿一致），「已隐藏」改用虚线弱框 + 徽标表示，
  不跟焦点抢同一个信号。
- **「媒体库」屏管的是文件本身，不是文件的登记表**（2026-09-22）：列表、上传、替代文本、
  删除都在这一屏，界面上每一个数字都是现场算出来的。四处刻意的取舍：
  1. **大小与尺寸以磁盘为准，不以库为准。** `media.bytes` 是上传时的快照，而随构建产物发布的
     种子图根本没有这个数（写入时是 0）。列表若直接读那一列，界面就会对着一堆真实存在的
     图片说「0 B」。所以每次请求都 `statSync` 一遍（PNG 另从 IHDR 读出尺寸，其它格式留空
     显示「—」，不猜）。**排序也因此必须在内存里做**：把「按大小」下推给 SQL 会去排那一列 0，
     点下去看着像没反应 —— 排序口径必须与界面显示的口径是同一个。
  2. **能不能删，取决于有没有人引用。** 引用关系散在文章封面、文章正文、站点设置与结构化区块
     四处，没有任何一张表记得住，所以是删除前现扫的。被引用时默认 409 拦下并原样带回引用清单，
     想删得传 `force=1` —— 这是管理员在看清代价之后的第二次确认，不是一条捷径。
  3. **上传走原始体，不引 multipart 依赖。** 前端 `fetch(url, { body: file })`，文件名进请求头、
     类型用 `Content-Type`；服务端就是一个挂在路由上的 `express.raw`（全局那个 32kb 的 JSON
     解析器按 Content-Type 分流，图片不会进它）。落盘名由服务端生成：ASCII 短名 + 短哈希，
     扩展名取自 MIME 而不是客户端给的文件名 —— 后者是访客说了算的，直接拼进路径等于让他决定
     写什么文件。
  4. **上传的 SVG 是可控的。** 直接访问一个 SVG，浏览器按文档渲染并执行里面的 `<script>`，
     于是「上传一张图」就等于「拿到一个同源 XSS 落点」。`/uploads/*` 因此带
     `X-Content-Type-Options: nosniff` 与 `Content-Security-Policy: default-src 'none'`；
     作为 `<img>` 引用时照常显示（CSP 约束的是文档，不是图片子资源）。
  界面与接口的两处「不做」同样是刻意的：**文件名只读且接口拒收改名**（它是磁盘路径与所有引用的
  锚点，改一次要同时动文件、库与四处引用，做一个只改一半的「重命名」比不做更糟）；
  **设计稿上的「新建文件夹」与「存储用量 24%」没有实现** —— 库里没有文件夹这一维，
  也没有配额这一说，那根百分比进度条只能编，所以换成了真实的文件数与字节数。
- **「分类与标签」屏管的是文章的两个归类维度，两者数据结构不同、规矩也不同**（2026-09-22）。
  分类名**直接存在** `posts.category` 字符串上（不是外键），标签是多对多（`post_tags` 中间表）。
  于是同一屏里出现了四处刻意的差异：
  1. **分类改名是连带写入，标签改名只动名字。** 分类名是文章上的那个字符串，只改 `categories.name`
     会让前台筛选条多出一个空分类、老文章全掉进「未分类」，所以 `renameCategory` 在同一个事务里
     连带 `UPDATE posts`；标签的关联按 id 走，叫什么名字都不影响它挂在哪些文章上。
  2. **分类有顺序、标签没有。** 分类的 `sort_order` 决定前台筛选条（`filters.blog`）排列，拖拽是
     真能改的；标签按使用频次降序（是算出来的，不是存的），所以不能拖。
  3. **删除的代价不同。** 删分类若挂着文章默认 409 并带回清单，`force=1` 才解绑（文章变「未分类」）；
     删标签只解关联、文章一篇不动（`post_tags` 级联）。
  4. **近重复两边规矩相反。** 分类在入口就拦（它没有合并入口，且名字会被写进文章，攒下
     `自 托管` / `自托管` 两条就再也合不起来）；标签放行 —— 文章编辑器里的标签输入框也会顺手建
     标签，拦不住，所以把它变成一件「看得见、能收拾」的事：列表随附近重复分组 +
     「合并重复标签」那个按钮。近重复判定走 `shared/taxonomy.mjs` 的 `normalizeName`
     （全角转半角、去空白与分隔符、统一小写），界面提示与后端拒收是同一份。
- **简历页（`/resume`）用的是示例履历**：结构为「个人概述 / 核心竞争力 / 工作经历 / 核心技能 /
  联系方式」五节，公司与项目名均为占位数据，替换成真实内容只需在后台「简历编辑」屏改，
  不必动代码。
- **简历页不提供下载 / 打印入口，履历正文禁止复制**（2026-09-19）：正文五个节（`ResumeSection`）
  带 `select-none`，并拦截右键、复制、剪切与拖拽；页头联系方式与姓名职位保持可复制，方便对方联系。
  这只提高复制门槛，**不构成安全边界**——查看源码、禁用 JS、截图 OCR 均仍可获取内容。
- **首页与作者卡的口径统一**：`hero.subline` / `hero.trust`、`profile.role`、`site.role` 与文章
  作者卡上的职位表述保持一致，「关于我」的时间线与简历页同源。首页「精选项目」的英文副标题用
  `/ Projects` 而非 `/ Open Source` —— 站上内容并非都以开源形式发布。
- **首页技术栈是一组示例标签**（Android / Kotlin / Java / OpenGL ES / FFmpeg / MediaCodec / libpag /
  Flutter / Unity3D / C / C++）：`skills` 标签墙与 `techStack` 卡片共用同一份
  `shared/content.mjs` 数据，`Icons.techIcon` 的名字映射与之同步；另有 `CubeIcon`（3D / 渲染）、
  `WaveIcon`（音视频）两个图标。
- **以下均是示例数据，接真实内容时替换**：
  - 项目 star 数 / forks、博客阅读量（`projects`、`posts`、`projectsPageStats`）目前是固定值。
  - 首页 `stats` 的四个数字、`strengths`（个人优势）、`projects` / `posts` 的语言与标签，
    都是建站时的示例内容。
- 项目页（`/projects`）的区块标题仍是「开源项目」，与首页的 `/ Projects` 不一致，待统一。
- `public/images/` 现只保留 Hero 与头像两张配图（AI 生成，内嵌 AIGC 合规标识并带可见水印）。
  文章封面不再随仓库分发，无封面时卡片回退 `cover-default.svg`（手绘矢量，非 AI 生成，
  图内不含文字，便于改名与复用）。换成真实素材时保持文件名语义化即可，无需改代码 ——
  但**封面路径要与文件同进同退**：库里留着指向已删文件的地址会绕过默认封面直接裂图。
- 简历的联系方式默认只展示邮箱与 GitHub，不含手机号。需要的话在 `resume.header.contacts`
  加一项，并补一个 `PhoneIcon` 组件。

  为它单开一屏比就地改更绕，所以编辑与新建走的是后台既有的弹层（`Modal`），没有新造一套交互。
  卡片右上角的「更多」菜单同理 —— 设计稿上那里只有一个拖拽把手，而删除、上下架需要一个去处。
  另外设计稿画的是**静态**排布，实现里排序是真能拖的（见 `AdminProjects` 顶部的取舍说明）。

  中文句式，否则界面会以「未登记动作」标记出来 —— 这是刻意的显式降级，不是遗漏。
- 媒体文件落本地目录（`UPLOAD_DIR`，默认 `data/uploads`，随 `/uploads/*` 同源托管），

- 暗色主题：设计稿上的主题切换入口已移除，本站只做浅色。如需暗色，在 `index.css` 补一套
